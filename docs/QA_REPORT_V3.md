## 발견 문제와 해결

| 위험/문제 | 조치 | 테스트 |
|---|---|---|
| 병원 청구 POST 성공 직후 GET이 가끔 미커밋 데이터 확인 | DB BEGIN IMMEDIATE + 성공 응답 전 명시 커밋 | 전체 39개 반복 3회 통과 |
| 연락처만 입력해도 캠페인 대상자로 계산되는 위험 | HMAC 해시 저장, 실소유권 미확인 상태라 발송대상 0명 | 테스트 31/32 |
| 데모 의료 사진을 실제 분석한 것처럼 보일 위험 | 이미지 분석 성공값 분리, 키 부재/실패 시 `image_analyzed:false` | 테스트 27 |
| 응급 상황에서도 광고 병원 우선하는 위험 | 긴급 키워드는 119 우선, 광고 목록 빈 배열 | 테스트 25 |
| 가상 수가가 공식 진료비 청구 가능액처럼 표시될 위험 | 내부 점검 차단, 공식 접수 상태 전환 불가 | 테스트 35 |
| 다른 의료기관 계정으로 재무정보 조회하는 위험 | 기관별 키 및 SQL provider_id 스코핑 | 테스트 35 |
| 개인정보가 광고주 통계에 노출될 위험 | 광고 보고서 합산 통계만 제공, 의료 텍스트 수집 안함 | 테스트 36 |

## 미검증 / 미구현 (정직한 범위)

- OpenAI 외부 실API를 호출해 실제 의료 사진/증상에 대한 임상적 정확도를 검증하지 않았음.
- CT, MRI, X-ray 해석, 의료기기 인증, 확정 진단, 처방 불가.
- 심평원 청구 포털 실제 전송/자동심사·건보공단 실제 입금, 마이헬스웨이 실데이터 본인인증 API, 문자/카카오 발송, 예약 확정, 쿠폰 결제/충전/환급 기능 없음.
- B2C 건강정보는 서버 영구 DB가 아닌 브라우저 메모리에서만 보관하고 사용자 직접 JSON 내보내기 방식.
- 현장 보안 침투테스트, 성능부하테스트, 외부 의료광고 심의 및 병원기관 실제 데이터 QA는 별도.
