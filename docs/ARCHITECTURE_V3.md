# MEDIPICK v3.1 기능 구조·데이터 흐름

```
사용자 웹: /index.html(의료지식 검색) /consult.html(멀티모달 상담)
     │         ├─ 글→일반 진료과·주의사항, 필요시 명시 동의 후 비전 모델
     │         └─ 유효구독+광고심사+진료과일치 병원 → 광고 분리 카드
     ├─ /my-health.html → 브라우저 메모리 및 JSON 파일 (민감정보 서버 전송 없음)
     └─ /doctors.html → Blogger 소유권 증명 → 운영자 승인 → 게시물 검수

병원 운영: /doctor-finance.html ─ 기관별 bearer key ─ billing.py
     ├─ 수가→비식별 청구초안→내부점검→외부포털 수동 접수기록
     ├─ 수동 심사인정액→은행 수동 입금→초과방지 대사→xlsx
     └─ billing_audit: 기관/담당키/행동/시간

마케팅: /marketing-console.html ─ 운영자 쿠키+CSRF 헤더 ─ engagement.py
     ├─ 수신 의사표시(해시, 미인증)→실제 전송 가능 대상은 0명
     ├─ 초안 작성 / 의료 유인 혜택 거부 / 모든 발송 비활성
     └─ 가상 체크인→보상 포인트 0

전국 실기관·실서비스 API는 계약/검증/운영 승인 전 미연결.
```

## 보안 선택

- 초안 진료비 정보: 방문참조 랜덤 영숫자만, 주민번호·환자 성명·의학상병 미저장.
- 변조된 구독기관 우선광고 차단: 만료일+결제+광고심사 승인+관련 진료과 동시 확인.
- 사진 원본: Pillow 검증·재인코딩·메타데이터 제거, DB 저장 0.
- 개인정보: 건강 기록은 브라우저 메모리, 연락처는 HMAC 해시, 사진 상담 질문은 서버 DB/URL에 저장하지 않음.
- 비전: 기본은 규칙 기반 안내(사진은 분석하지 않았다고 알림), 명시 동의 및 유효 외부 API 키 존재 시 요청.
- 긴급 키워드: 119 안내 우선; 의학적 민감성과 한계 때문에 검증된 응급 판단기라는 표현 금지.
- 금융/청구: 명시적 BEGIN IMMEDIATE 트랜잭션, HTTP 성공 응답 전 COMMIT, 초과 입금 배분 검사.

## 알려진 위험·추가 개발 우선순위

1. 고급 임상 안전 게이트: 의료전문의 감독 하에 시나리오별 검증, 부적절 진단 금지, 응급질환 민감도 평가.
2. 기관별 보안: 조직별 MFA, RBAC, 키 회전, 환자/의사 역할분리, TLS 및 암호화 저장, 백업·삭제 기능.
3. 공공/실기관 데이터: 공식 API 계약·동기화, 임상 표준코드/치료 가이드라인 업데이트, 출처 버전.
4. 실제 의료광고 심의·개인정보/마케팅 규정 정기 점검 및 수신 동의 실소유권 검증.
5. 현장 병원 상담 연결과 실제 스케줄 확정: EMR/캘린더 통합은 인증된 기관 계약 후 별도.
