# MEDIPICK 1.0 검수 결과 (2026-10-29)

## 실제 수행한 검증

- `python -m unittest discover -s tests -v` : **14/14 통과** (최종 실행 환경에서 1.1~1.6초 범위)
- `python -m py_compile server.py ai_service.py scripts/*.py` : 문법 검사 통과
- `node --check web/assets/app.js`, `node --check web/assets/admin.js`, `node --check web/assets/advertiser.js` : JavaScript 문법 검사 통과
- HTML/CSS 화면 모의 응답 브라우저 렌더링: 홈 카테고리 12개, 스폰서 3개, 의료기관 상세 모달, 운영자 KPI 4개 표시, 모바일 화면 가로 넘침 없음, 브라우저 JS 예외 없음
- API 테스트: 일반 방문자 기관검색(광고 우선순위), 심야약국 자연어 분류, 상세의료진 조회, 관리자 미인증 거절, 조회/검색 통계, 기관 추가, 의사 콘텐츠 승인, 업종 불일치 광고 차단, 예약 요청·알림 대기함·ICS 캘린더, 후기 금지어 및 운영자 승인, 입력 검증
- **실제로 발견·수정한 문제:** API의 저장 직후 조회가 비동기 서버 스레드 사이에서 간헐적으로 커밋보다 빨라 일치하지 않던 현상. DB 작업을 원자적 autocommit 방식으로 변경한 후 자동 테스트 14/14 통과.
- **추가 수정:** 유료 광고와 무관하게 기관 상세를 클릭했을 때 광고 클릭으로 오집계될 가능성 → 스폰서 카드 클릭 시에만 `ad_click` 기록하도록 분리.
- **광고주 계정 경계 검증:** 무인증 광고주 리포트 차단, 기관별 서명 조회키 발급, 관리자 키 목록에서 원본 비밀키 비노출, 기관별 집계만 공개, 폐기 시 즉시 접근 거절을 실제 API 13번째 테스트로 검증. AI 동의 없는 내부 콘텐츠 요약 응답도 14번째 테스트로 검증.
- **추가 개선:** 실제 의사 자격 검증 전에 작성된 콘텐츠는 `작성자 검증 전` 표시, 운영자 콘텐츠 등록 시 의료진 ID 선택 기능 추가.

## 검증 범위의 정확한 한계

- 로컬 HTTP API는 Python 테스트 클라이언트로 실제 실행·검증했습니다. 이 세션 Chromium은 **localhost URL 직접 접근을 정책상 차단**하여 서버와 연결된 완전한 브라우저 E2E는 불가했습니다. 따라서 페이지 화면은 `set_content`/모의 응답을 통한 렌더링 검사를 수행했습니다. 진짜 브라우저 전 과정 사용은 납품 환경에서 다시 검증해야 합니다.
- 실 병·의원 데이터(API 키 미제공), 전문의 소속/학회 자격 검증, 심야약국 실제 영업시간, Google 블로그 및 YouTube 채널 API 연결, 병원 실예약, 카카오/SMS·Google Calendar·GA4 실서비스 계정 연동은 수행하지 않았습니다.
- 실제 광고 계약 및 과금, 프로덕션 보안 테스트, 개인정보 보유기간/자동삭제, 웹서버 고부하 테스트, 공식 의료광고 사전심의는 수행하지 않았습니다.
- 모바일/데스크톱 반응형 디자인은 시각 렌더링만 확인하였고 모든 휴대전화 모델의 접근성·기기 테스트는 하지 않았습니다.

## 검증 우선순위

**치명적 (상용 오픈 전 필수):** 개인정보 수집 및 의료광고 적법성, 의료진 자격 증명, 실영업 검증, 의료기관 실예약 확정, 안전한 DB/HTTPS/접근제어, 데이터 삭제, 광고계약/정산.

**중요:** 외부 콘텐츠 자동 가져오기 권리 검증, 예외/재시도, AI 의학정보 원문 출처 검증, 분석 이벤트 실제 값 대조, 예약 충돌 및 중복 접수 대책.

**디자인 품질:** 의료기관 사진 사용권/제작, 상세페이지 맞춤 이미지, 카드 정보 밀도 최적화, 모바일 소형화면 및 접근성 정밀 검사.
